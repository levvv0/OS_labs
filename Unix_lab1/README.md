# Лабораторная работа №1. Скрипт сборки C++

## Файлы

- `build.sh` — POSIX Shell-скрипт;
- `hello.cpp` — пример исходного файла.

## Запуск

Сначала нужно разрешить выполнение скрипта:

```sh
chmod +x build.sh
```

Затем выполнить сборку:

```sh
./build.sh hello.cpp
```

В `hello.cpp` находится специальный комментарий:

```cpp
// Output: hello
```

Поэтому после успешной сборки рядом с исходным файлом появится исполняемый файл `hello`. Его запуск:

```sh
./hello
```

Результат:

```text
Hello from C++!
```

Код завершения последней команды можно посмотреть так:

```sh
echo $?
```

## Как работает скрипт

1. Проверяет, что передан один существующий файл `.cpp`.
2. При помощи `sed` находит комментарий `// Output: имя_файла`.
3. Устанавливает `trap` для очистки при обычном завершении, ошибке и перечисленных ниже сигналах.
4. Создаёт временный каталог командой `mktemp -d`.
5. Копирует исходный файл во временный каталог командой `cp`.
6. Во временном каталоге компилирует программу командой `g++`.
7. Командой `mv` переносит результат рядом с исходным файлом.

`SIGKILL` и `SIGSTOP` обработать нельзя: операционная система не позволяет процессу перехватывать эти сигналы. Обработчик устанавливается до `mktemp -d`. Если сигнал поступит во время создания каталога, скрипт запомнит его и завершится после получения пути к каталогу. При аварийной остановке в любой момент POSIX Shell всё же не может гарантировать очистку.

Если оболочка получила какой-либо сигнал уже проигнорированным, она не может назначить для него обработчик. Это может относиться, например, к `QUIT` или `PIPE` в некоторых условиях запуска.

## Коды завершения

| Код | Значение |
|---:|---|
| 0 | Успешная сборка |
| 1 | Неверное количество аргументов |
| 2 | Исходный файл не найден |
| 3 | Передан не `.cpp` файл |
| 4 | Не найден корректный комментарий `Output` |
| 5 | Не удалось создать временный каталог |
| 6 | Не удалось скопировать исходный файл |
| 7 | Ошибка компиляции |
| 8 | Не удалось сохранить результат |
| 129 | Получен `SIGHUP` |
| 130 | Получен `SIGINT`, например после `Ctrl+C` |
| 131 | Получен `SIGQUIT` |
| 134 | Получен `SIGABRT` |
| 138 | Получен `SIGUSR1` |
| 140 | Получен `SIGUSR2` |
| 141 | Получен `SIGPIPE` |
| 142 | Получен `SIGALRM` |
| 143 | Получен `SIGTERM` |
| 152 | Получен `SIGXCPU` |
| 153 | Получен `SIGXFSZ` |

Коды для сигналов указаны по принятому в Linux соглашению `128 + номер сигнала`.

## Проверка ошибок

Запуск без аргументов должен завершиться с кодом `1`:

```sh
./build.sh
echo $?
```

Запуск с отсутствующим файлом должен завершиться с кодом `2`:

```sh
./build.sh missing.cpp
echo $?
```

Если удалить комментарий `Output` из `hello.cpp`, скрипт должен завершиться с кодом `4`. Если допустить синтаксическую ошибку в C++, должен вернуться код `7`.
